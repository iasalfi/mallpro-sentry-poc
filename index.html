What this camera is doing

Positioned overhead at the doorway, exactly as recommended for accuracy. The amber line is the counting line; each tracked person gets a bounding box and ID, and a crossing is logged the instant the box passes the line — direction included, so double-counting on hesitation is filtered out.

This count is body detection, not face recognition. Abaya, hijab or niqab don't change it — every crossing is counted the same way. Face-dependent detail lives one tab over, in Visitors.
Module A+ · Visitor insight (optional)

Visitors & demographics

Every crossing at the entrance line gets a gender and age-band estimate, from a face read where one is available and from body cues where it isn't. Aggregate only — no identity is stored or matched to a person.

Face signatures: memory-only, auto-expire
Face visibility in a KSA mall

Hijab covers the hair, not the face, so it doesn't affect estimation at all — SCRFD still finds the face and InsightFace still reads it. Niqab or burqa is the real variable: the face is covered, but the covering itself is a strong gender signal, so MallPro still classifies the visit as female and falls back to a body-cue model — height, build and gait — for a coarser age band. Every such read is tagged body-cue with a lower confidence score, never presented as a face match. Use the control below to see how the mix shifts at a more conservative site.
